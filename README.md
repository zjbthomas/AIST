# 明日方舟集成战略记录器

一个本地优先、无需账号和后端服务器的《明日方舟》集成战略时间轴记录与统计工具。

项目使用 React、TypeScript 和 Vite。运行记录默认保存在用户自己的浏览器中，也可以导出为 JSON，在其他浏览器或设备中重新导入。

## 功能

### 单局记录

- 选择集成战略主题和分队
- 按楼层添加、删除关卡节点
- 从 PRTS 数据中搜索和添加干员
- 记录普通招募或临时招募
- 记录干员精英化一、精英化二状态
- 记录每场战斗是否上场及使用技能
- 使用干员头像、精英化图标和技能图标显示状态
- 使用时间线连接招募后的连续节点
- 自动统计单局干员编队次数、部署次数和技能使用次数
- 支持干员筛选和排序

### 记录管理

- 新建多个记录
- 切换、读取和删除记录
- 自动保存到 `localStorage`
- 导出全部记录为 JSON
- 从 JSON 导入记录

### 综合统计

综合统计页面可以同时分析：

- 任意多个本地记录
- 一次导入的多个 JSON 文件
- 不同集成战略主题

统计内容包括：

- 普通招募次数
- 临时招募次数
- 普通招募干员编队次数
- 临时招募干员编队次数
- 总编队次数
- 出现记录数

支持按干员名称、星级、主题、招募类型进行筛选，并按抓取次数、编队次数、部署次数、出现记录数、星级或名称排序。

导入到综合统计区域的 JSON 仅用于当前分析，不会覆盖浏览器中的本地记录。

## 本地运行

需要 Node.js 20 或更新版本。

```bash
npm install
npm run dev
```

Vite 会在终端中显示本地访问地址，通常为：

```text
http://localhost:5173
```

## 构建

```bash
npm run build
npm run preview
```

构建结果位于：

```text
dist/
```


### 干员头像全部显示占位图

旧版本将头像保存为 `Special:Redirect/file` 跳转地址，浏览器可能无法直接加载。更新代码后强制重新同步：

```bash
npm run sync:prts
```

新同步器通过 MediaWiki `imageinfo` API 保存真实的 `media.prts.wiki` 图片地址，并会校验至少 90% 的干员成功获得头像。同步后请硬刷新页面；若浏览器仍使用旧数据，可在开发者工具中清除站点缓存后重试。

## PRTS 数据同步

项目通过 PRTS MediaWiki API 获取干员、头像、技能图标和集成战略关卡数据。

完整同步：

```bash
npm run sync:prts
```

只同步关卡：

```bash
npm run sync:stages
```

同步结果写入：

```text
public/data/operators.json
public/data/stages.json
public/data/manifest.json
```

同步脚本位于：

```text
scripts/sync-prts.mjs
```

`npm run dev` 和 `npm run build` 执行前也会运行数据检查。已有数据仍然较新时，脚本可以跳过重复同步。

### 同步失败排查

先检查 PRTS API 是否可以从当前网络访问：

```bash
curl -I https://prts.wiki/api.php
curl "https://prts.wiki/api.php?action=query&meta=siteinfo&format=json"
```

如关卡页面可以下载但解析失败，调试 HTML 会保存在：

```text
public/data/debug/
```

这些调试文件已被 `.gitignore` 忽略。

## 数据保存说明

应用目前没有后端数据库。每个用户的记录保存在该浏览器、该域名对应的 `localStorage` 中。

因此：

- 清理浏览器站点数据可能删除记录
- 更换浏览器或设备不会自动同步
- 建议定期导出 JSON 备份
- GitHub Pages 域名或仓库路径变化后，旧地址的数据不会自动迁移

## 无服务器公开发布

该项目适合发布为静态网页，不需要自行维护服务器。

推荐使用 GitHub Pages。项目已包含：

```text
.github/workflows/deploy-pages.yml
```

发布步骤：

1. 创建 GitHub 仓库并推送项目。
2. 打开仓库的 **Settings → Pages**。
3. 将 Source 设置为 **GitHub Actions**。
4. 推送到 `main` 分支，或手动运行部署工作流。
5. GitHub Actions 构建并发布 `dist/`。

每位使用者打开网页后，记录仍然只保存在自己的浏览器中。

## 为什么不是 Chrome Extension

当前功能不需要读取或修改其他网页，也不依赖浏览器扩展权限。因此静态网页更合适：

- Chrome、Edge、Firefox、Safari 都可以使用
- 手机浏览器也能访问
- 用户不需要安装插件
- 不需要 Chrome Web Store 审核
- 可直接使用 GitHub Pages 免费托管

以后若要从 PRTS 页面或直播页面一键导入内容，可以再单独增加一个轻量浏览器扩展，与现有网页共用 JSON 数据格式。

## 数据来源与声明

干员、技能、关卡名称和相关图片信息来自 PRTS Wiki。项目与鹰角网络、Hypergryph 和 PRTS Wiki 无官方关联。

公开发布或重新分发相关数据和图片前，请自行确认 PRTS Wiki 的许可条款以及游戏素材的版权要求。建议在应用中保留数据来源和跳转到 PRTS 的链接。

## 当前限制

- 没有云同步或多人协作
- 浏览器数据需要用户自行备份
- PRTS 页面结构变化时，同步解析器可能需要更新
- 当前仍属于早期版本，建议先用少量记录验证数据格式后再大规模录入

### 同步显示 `0/427` 个干员头像

旧同步器假设头像文件名一定是 `头像_<干员名>.png`，但 PRTS 的文件名、重定向和别名并不统一。当前版本会：

1. 使用 MediaWiki `pageimages` 查询干员页面主图；
2. 若页面没有主图，从该页面实际引用的图片文件中筛选头像；
3. 再通过 `imageinfo` 获取真实媒体 URL。

更新项目后请强制重新同步：

```bash
npm run sync:prts
```

## 分队数据

同步脚本会从每个集成战略主题页面的分队表格提取分队，并生成 `public/data/squads.json`。前端切换主题时，只显示该主题实际拥有的分队。运行：

```bash
npm run sync:prts
```

或仅刷新关卡与分队：

```bash
npm run sync:stages
```

## 技能图标同步

技能文件链接采用 PRTS 干员页实际使用的百分号编码格式解析，并按 MediaWiki 文件 MD5 路径生成 `media.prts.wiki` 地址。同步日志中的 `Skills:` 应不再为 0。机器人及部分特殊干员没有普通技能属于正常情况。

## 网站预设记录

项目支持把你准备好的记录作为公开预设随 GitHub Pages 一起发布。访问者可以：

- 在顶部点击“预设”浏览网站预设；
- 以只读方式打开预设记录；
- 把预设复制成自己的本地记录后继续编辑；
- 在“综合抓位与使用统计”中勾选预设，与本地记录或导入 JSON 一起统计。

### 添加预设

1. 在网页中完成记录并导出 JSON。
2. 把导出的 JSON 放到 `public/presets/`，例如：

```text
public/presets/xianshu-final-player-a.json
```

3. 编辑 `public/presets/index.json`：

```json
[
  {
    "id": "xianshu-final-player-a",
    "name": "仙术杯决赛 · 选手 A",
    "description": "决赛第一局的抓取、编队与部署记录",
    "theme": "沉沦者的黑流树海",
    "squad": "分队名称",
    "author": "记录整理者",
    "event": "仙术杯",
    "date": "2026-08-03",
    "tags": ["决赛", "通关"],
    "file": "xianshu-final-player-a.json"
  }
]
```

`file` 必须是相对于 `public/presets/` 的文件名。预设 JSON 可以是单个 `RunState`，也可以是应用导出的完整 `TrackerStore`；完整存档中会读取第一个记录。

预设文件会公开部署，任何访问者都可以查看和下载，因此不要放入私人备注或未公开信息。


## 关卡后晋升与技能数量

- 点击干员与关卡的交叉格，可标记“本关后晋升精英化二”。该关卡仍显示晋升前状态，精英化二从下一个节点开始生效。
- 时间轴会在晋升发生的关卡显示“→ 精二”图标。
- 技能选择数量来自 PRTS 同步结果中的 `operator.skills`，前端不再按星级硬编码显示三个技能。


## 干员筛选与搜索

添加干员窗口支持八职业筛选：先锋、近卫、重装、狙击、术师、医疗、辅助和特种。搜索框支持中文、无声调拼音以及拼音首字母，例如 `棘刺`、`jici`、`jc` 都可以命中棘刺。拼音搜索由 `pinyin-pro` 在浏览器本地完成。

同步生成的 `operators.json` 会保存 PRTS `data-profession` 字段。更新本版本后请重新运行：

```bash
npm run sync:prts
```

## GitHub Pages

仓库包含 `.github/workflows/deploy-pages.yml`。由于发布包不预生成 `package-lock.json`，工作流默认使用 `npm install`。你在本地运行 `npm install` 并提交 `package-lock.json` 后，可以将工作流改成 `npm ci`，获得完全可复现的安装。

### 作战类型

PRTS 同步数据会区分普通作战、紧急作战、区域最终战斗和特殊作战。添加关卡时可以按作战类型筛选，时间轴表头也会显示对应类别。旧记录没有类别字段时默认按普通作战兼容读取。

## 动态关卡区块同步

关卡同步不再把所有肉鸽写死为“普通 / 紧急 / Boss / 特殊”四种类别，而是逐个解析每个主题“关卡一览”中的真实 `ISW-*` 表格：

- 保存 `sectionCode`，例如 `ISW-NO`、`ISW-DF`、`ISW-DU`、`ISW-SP`；
- 保存 PRTS 当前显示的 `sectionName`；
- `一般作战 & 紧急作战` 区块中的每个关卡同时展开为“一般作战”和“紧急作战”两个可选版本；
- 其他区块保持原始名称，不对“险路恶敌”“鸭爵表演”“特殊挑战”或新主题新增区块做硬编码；
- `[Ⅰ]`、`[Ⅱ]`、`[Ⅲ]` 等内容扩展脚注会被忽略；
- 没有固定楼层的特殊区块，在添加关卡时由用户选择记录到哪一层；
- 同步时额外生成 `public/data/stage-categories.json`，用于检查每个主题实际识别到的类别和数量。

运行：

```bash
npm run sync:stages
```

日志会按主题输出真实类别，例如：

```text
Stages: 某主题 -> 120
  Categories: 一般作战(40)、紧急作战(40)、险路恶敌(12)、……
```

如果 PRTS 改动导致某主题只解析到少量关卡、没有识别到多个类别，或一般/紧急作战的关卡集合不一致，同步会拒绝覆盖现有数据，并把页面保存到 `public/data/debug/`。

### `Skills: 0/0 operators`

若旧版本出现该日志，原因是同步器向 `action=parse` 传入了无效的 `wikitext` prop，导致所有干员详情请求失败。当前版本已改为 `prop=text|revid`，并会输出每批请求的首个真实失败原因。

### PRTS 关卡表解析说明

同步器不会假设每个肉鸽拥有相同的关卡类别。它会从“关卡一览”章节中读取真实的 `ISW-*` 区块，并使用嵌套表格的叶子行进行解析。PRTS 常将实际关卡表包在一层或多层外部表格中，因此不能只读取最外层或单张表的直接行。

当前实现保留 `THEME_STAGE_ADAPTERS` 扩展入口；以后若某个主题采用完全不同的 DOM，可以只为该主题增加适配器，而不影响其他主题。

### 新增关卡时的状态继承

新增关卡后，系统会自动复制时间轴中前一节点的出战/未出战状态及所选技能，方便连续记录。招募、临时招募和关卡后晋升属于一次性事件，不会复制到新关卡。

### 图片楼层识别

部分主题（例如岁的界园志异）在 PRTS 关卡表中使用图片而不是罗马数字表示楼层。同步器会识别“首格为图片、同一行其余单元格为关卡”的结构，并按图片行出现顺序映射为第 1、2、3……层。若某些关卡仍无法识别楼层，添加关卡窗口会显示提示，并允许手动指定层数。

### 关卡节点状态与图片楼层（本版修复）

- 新增关卡时，该节点的出战状态、技能、招募和晋升设置全部为空，不再复制前一关。
- 对使用图片表示楼层的主题，同步器优先读取图片 `alt`、`title`、链接标题和文件名中的明确层数。
- 若图片本身没有层数文字，只会从该主题完整的“一般作战 & 紧急作战”主表学习图片与绝对楼层的对应关系，再把同一图片映射复用于“险路恶敌”等区块。
- 不会在每个区块中把第一张图片当作第一层。因此从第三层开始的 Boss 区块不会被错误映射为第一层。
- 无法可靠确认的楼层会保留为 `floor: 0`，前端标记为“自选”，而不是猜测。


## 其它节点类型

PRTS 同步会从每个主题主页的“事件节点”章节生成 `public/data/node-types.json`。添加其它节点时，界面会按当前集成战略动态显示可用的非作战节点，例如不期而遇、得偿所愿、安全屋、幕间余兴和诡意行商。若 PRTS 页面结构暂时无法识别，会自动补充基础节点，并保留“自定义节点”。

### 非作战节点晋升与进入新一层

- 已招募且当前为精英化一的干员，可以在作战或非作战节点标记“此节点后晋升精英化二”。
- 晋升从时间线的下一个节点开始生效。
- “添加其它节点”中固定提供“（进入新一层）”，用于记录先行一步、树洞等在换层时结算的延后晋升。
- 非作战节点不记录编队、部署和技能，也不会作为后续作战节点继承阵容的来源。

## 节点编辑与排序

- 时间线节点标题右下角的铅笔按钮可修改节点。
- 作战节点可以更换楼层和具体关卡；其它节点可以更换楼层、类型和名称，也可在两类节点之间转换。
- 除初始节点外，可直接拖动节点标题调整时间线顺序。节点对应的整列干员状态会随节点一起移动，不会丢失或错位。
